NanoClaw 代码逻辑运行图

多渠道智能体：飞书 / QQ / 终端 / Web → 消息总线 → 网关 → AgentLoop → 工具/LLM

模块结构 全流程总图 启动流程 消息路由 Agent 循环 四渠道时序 端到端时序 数据落盘

1. 项目模块结构

各目录与文件的职责分工。

nanoclaw/
├── main.py                  # 入口：工作目录固定、编码兜底、启动配置/MCP/渠道/网关
├── config.py                # 读取 config.json
├── gateway.py               # 网关：消息路由、会话级并发调度
├── bus/queue.py             # 消息总线（入站/出站异步队列）
├── channels/                # 渠道适配层
│   ├── base.py              #   渠道抽象基类
│   ├── cli.py               #   终端渠道（stdin）
│   ├── feishu.py            #   飞书渠道（lark WebSocket，子线程投递）
│   ├── qq.py                #   QQ 渠道（botpy，原生异步）
│   └── web.py               #   Web 渠道（FastAPI + WebSocket）
├── agent/
│   ├── loop.py              # AgentLoop：LLM 多轮推理 + 工具调用
│   ├── context.py           # 组装 System Prompt（人设/时间/记忆/技能）
│   ├── memory.py            # Token 估算 + 历史压缩
│   ├── skills.py            # 技能（SKILL.md）加载器
│   └── tools/               # 工具层
│       ├── base.py          #   工具抽象基类
│       ├── registry.py      #   工具注册表（异常兜底）
│       ├── filesystem.py    #   读写文件/列目录（workspace 边界防穿越）
│       ├── shell.py         #   执行命令
│       ├── web_search.py    #   Bing 搜索
│       ├── web_fetch.py     #   网页抓取
│       ├── spawn.py         #   子 Agent
│       └── mcp_server.py    #   MCP 客户端管理 + MCP 工具包装
├── providers/
│   ├── base.py              # LLM Provider 抽象
│   └── openai_compat.py     # OpenAI 兼容 API（硅基流动）
├── session/manager.py       # 会话历史持久化（jsonl）
├── mcp_servers/poetry_server.py  # 自建 MCP：古诗词服务
├── skills/                  # 技能定义（weather / translator / code_review）
└── workspace/               # 运行时数据（会话记录、长期记忆）

5. AgentLoop 核心循环

LLM 多轮推理 + 工具调用 + Token 压缩。

flowchart TD
    S["收到用户消息"] --> H["SessionManager 加载历史
追加用户消息并保存"]
    H --> CTX["ContextBuilder.build_messages
人设 identity.md + 当前时间
+ workspace 路径 + MEMORY.md
+ 技能摘要 + 历史 + 当前消息"]
    CTX --> CHK{"历史超 Token 预算?"}
    CHK -->|是| COM["MemoryConsolidator
压缩旧消息为摘要
写入 HISTORY.md"]
    CHK -->|否| LOOP
    COM --> LOOP["provider.chat
调用 LLM 携带工具定义"]
    LOOP --> RES{"返回内容?"}
    RES -->|纯文本| OUT["保存助手消息
返回给渠道"]
    RES -->|tool_calls| EXE["ToolRegistry.execute
read_file / write_file / list_dir
exec / web_search / web_fetch
spawn_subagent / MCP 工具"]
    EXE --> APP["工具结果追加为 tool 消息"]
    APP --> CHK2{"达 max_iterations?"}
    CHK2 -->|否| CHK
    CHK2 -->|是| OUT

6. 四渠道收发时序

核心下游完全共用，区别只在接入层。

飞书：子线程回调 → 投回主循环 → 同步 API 回复

sequenceDiagram
    participant U as 用户(飞书App)
    participant SDK as lark ws.Client(子线程)
    participant MAIN as 主事件循环
    participant GW as Gateway
    participant AG as Agent
    participant API as 飞书 OpenAPI
    U->>SDK: 发消息(经飞书服务器WS推送)
    SDK->>SDK: _on_message 解析
    SDK->>MAIN: run_coroutine_threadsafe 投递
    MAIN->>GW: consume_inbound
    GW->>AG: agent.run(text)
    AG-->>GW: 回复
    GW->>SDK: send() 空内容保护+重试1次
    SDK->>API: im.v1.message.create(to_thread)
    API->>U: 回复送达

QQ：botpy 原生异步，链路最短

sequenceDiagram
    participant U as 用户(QQ)
    participant B as botpy.Client(主循环)
    participant GW as Gateway
    participant AG as Agent
    participant API as QQ OpenAPI
    U->>B: @机器人/私聊(平台WS推送)
    B->>GW: await publish_inbound
    GW->>AG: agent.run(content)
    AG-->>GW: 回复
    GW->>B: send()
    B->>API: 先发 C2C 消息
    alt C2C 失败
        B->>API: 回退发群消息
    end
    API->>U: 回复送达

终端：input 阻塞在 to_thread，print 回复

sequenceDiagram
    participant U as 用户
    participant C as CLIChannel
    participant GW as Gateway
    participant AG as Agent
    U->>C: 键盘输入
    C->>C: input() 在 to_thread
本地命令 /exit /clear /tools
    C->>GW: publish_inbound(cli:local)
    GW->>AG: agent.run(text)
    AG-->>GW: 回复
    GW->>C: send()

Web：每标签页独立 uuid 会话

sequenceDiagram
    participant B as 浏览器
    participant S as FastAPI(主循环)
    participant GW as Gateway
    participant AG as Agent
    B->>S: GET / 请求页面
    S->>B: 返回 index.html
    B->>S: WS 连接 /ws

    end

7. 端到端完整时序（内部组件视角）

任何渠道只有首尾两步不同，中间全走同一条管道。

sequenceDiagram
    autonumber
    participant U as 用户
    participant C as 渠道层
    participant B as MessageBus
    participant G as Gateway
    participant S as SessionManager
    participant X as ContextBuilder
    participant L as LLM(硅基流动)
    participant T as 工具/MCP
    participant M as MemoryConsolidator
    U->>C: 发消息
    C->>B: publish_inbound
    B->>G: consume_inbound → 会话队列
    G->>S: 加载会话历史
    G->>M: 历史超预算? 压缩为摘要
    G->>X: 组装 messages
    G->>L: chat(messages, tools)
    loop 最多 max_iterations 轮
        L-->>G: tool_calls
        G->>T: 执行工具(异常兜底)
        T-->>G: 工具结果
        G->>L: 带结果继续
    end
    L-->>G: 最终文本
    G->>S: 保存消息 jsonl
    G->>B: publish_outbound
    B->>C: 按 channel 名路由
    C->>U: 回复送达
